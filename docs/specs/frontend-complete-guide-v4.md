# Frontend Complete Guide v4

状态：已完成
基线日期：2026-08-15

## 1. 目标

基于当前融合工程的真实代码，形成一份适用于校招面试复习和项目讲解的完整前端手册，并再次区分：

- 能由现有 DOM、代码路径或验证结果明确证明的问题：本阶段修复；
- 只有在数据量、用户量或团队规模增长后才有收益的方案：仅作为后续演进回答；
- 不修改 AI Provider、Agent Loop、RAG 检索、服务端协议、Prisma 和两个只读参考项目。

## 2. 确认缺陷

### P1-1：AI 会话项存在嵌套交互语义

会话列表将整个 `List.Item` 标记为 `role="button"`，内部同时包含“更多操作”按钮。虽然已经支持 Enter/Space，但父级按钮语义包含另一个可聚焦按钮，不符合可访问交互组件应彼此独立的原则，读屏器可能无法清楚区分“选择会话”和“管理会话”。

修复要求：

- 会话选择使用原生 `button`，自动获得 Enter/Space 行为；
- 更多操作继续作为独立按钮，与选择按钮并列；
- 两个按钮拥有独立可访问名称，点击菜单不得切换会话；
- 保持当前选中态、生成态、置顶、分组和视觉层级。

### P1-2：少量辅助读取仍存在上下文切换竞态

阶段 39 已治理工作台、订单详情、店铺刊登、规则列表和 AI 会话列表，但完整遍历后仍发现以下辅助读取会直接提交异步结果：

- 订单保存视图在切换商家时可能短暂显示或提交旧商家视图；
- AI 内部分享弹窗快速切换会话时，旧会话的收件人或分享记录可能覆盖新会话；
- AI 分享页切换分享 ID/商家时，迟到响应可能覆盖当前快照；
- 规则文档详情和测试检索快速切换目标时，迟到响应可能覆盖最新结果。

修复要求：

- 继续复用阶段 39 的最新请求令牌，不新增状态库；
- 可见数据按 merchantId、sessionId 或 shareId 绑定；
- 关闭弹窗或切换商家时立即使旧请求失效；
- 不改变 API、权限、RAG 检索逻辑和服务端协议。

### P2-1：README 验证数字已经过期

README 仍声明 192/198 项测试和旧构建体积，与阶段 39 的 222 项测试及最新构建结果不一致，会削弱面试证据的可信度。

修复要求：

- README 统一使用最近一次完整 `verify` 的结果；
- 明确 222 条是单元、组件和集成测试总数，3 条 Playwright E2E 独立执行；
- 更新最大业务页面 chunk 的当前构建口径；
- 在 README 文档入口增加本阶段生成的前端完整手册。

## 3. 完整手册范围

手册必须包含：

1. 项目定位与前端职责边界；
2. 技术栈、目录结构和应用启动顺序；
3. 登录恢复、RBAC、商家/店铺上下文；
4. Redux 与 TanStack Query 的分工；
5. 工作台、商品/SKU、订单、导入、任务、规则和用户管理；
6. 统一 AI 会话、跨会话并发、SSE 降级、分叉树和人工确认；
7. 国际化、错误处理、性能、测试与交付；
8. 至少 6 组可直接复述的 STAR；
9. 已修复缺陷、真实限制、后续优化和禁止夸大的边界；
10. 3 分钟、8 分钟和追问式讲解建议。

## 5. 后续演进，不在本阶段实施

- 为超长消息或超大表格引入虚拟列表；
- 将所有辅助 CRUD 页面迁移到 TanStack Query；
- 建立全站 Storybook、设计系统或微前端；
- 使用 WebSocket 替换已经满足需求的 SSE + 有界查询恢复；
- 为当前最多 1000 行的导入预览引入 Web Worker；
- 追求 100% 测试覆盖率；
- 在没有真实生产用户前接入重型前端可观测平台。

这些内容只能作为条件触发的演进方案，不能描述成当前缺陷或已经实现的能力。
