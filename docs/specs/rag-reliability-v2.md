# RAG 可靠性完善 Spec（v2）

## 1. 目标

在不引入向量数据库、Reranker 或复杂编排框架的前提下，把现有规则 RAG 从“小型演示检索”升级为可评估、可治理、可校验的业务闭环。

## 2. 非目标

- 不引入 Elasticsearch、Milvus、GraphRAG 或新的外部基础设施。
- 不自动抓取第三方平台规则。
- 不使用模型作为 CI 评估裁判，保证回归测试确定、免费且可复现。
- 不宣称固定离线集代表生产环境效果。

## 3. 阶段一：离线评估基线

### 范围

- 建立不少于 30 条的固定标注集，包含直接命中、改写、中英混合、多文档、无答案和边界场景。
- 同时计算 Hit@1、Recall@3、MRR 和无答案拒答准确率。
- 评估作为 API 自动化测试运行，指标下降时阻断 CI。

### 验收标准

- 用例总数不少于 30，且无答案用例不少于 8。
- Hit@1、Recall@3、MRR、拒答准确率均在测试输出和断言中体现。
- README 明确数据集规模和离线评估边界。

## 4. 阶段二：规则适用范围与版本治理

### 范围

规则文档新增以下可选元数据：

- `market`：目标市场，例如 `US`、`BR`。
- `language`：规则原文语言，例如 `zh-CN`、`en-US`。
- `category`：适用商品类目。
- `effectiveFrom` / `effectiveTo`：生效区间。
- `version`：来源侧版本标识。
- `supersedesDocumentId`：被当前版本替代的文档。

检索请求允许传入 `platform`、`market`、`category` 和 `asOf`。权限、状态、适用范围和时间过滤必须在相关性排序之前完成。新文档声明替代旧文档后，旧文档归档；历史工具结果仍保留当时的引用快照。

### 验收标准

- 跨商家规则在候选召回前被排除。
- 平台、市场、类目不匹配及未生效/已失效文档不参与排序。
- 替代关系只能指向当前调用者可管理、平台一致的有效文档。
- 导入、替代归档及元数据进入审计记录。

## 5. 阶段三：检索与引用可靠性

### 范围

- 保留词项频次，不再因去重导致词频恒为 1。
- 使用可解释的 BM25 风格评分，保留标题权重和短语权重。
- 对同一文档的相邻 Chunk 做结果多样性控制。
- 使用最小分数、查询覆盖率和 Top1/Top2 差距共同形成拒答决策。
- 增加确定性的引用校验：回答只能引用工具实际返回的编号；无充分来源时不能输出规则结论。
- 对候选规模上限显式返回诊断，不允许静默截断却仍声称结果充分。

### 验收标准

- 排名结果包含命中词、覆盖率和可解释分数。
- 返回 `sufficient=false` 时包含机器可读原因。
- 非法引用能够被检测；无来源回答能够被降级为信息不足。
- 自动化测试覆盖相邻 Chunk 去重、弱命中拒答、候选截断和引用校验。

## 6. 面试口径

完成后统一表述为：项目使用适合小型规则库的可解释词法检索，并通过业务元数据前置过滤、Chunk 级引用、可靠拒答、生成后引用校验和固定离线评估保证安全边界；向量检索仅作为未来需要用同一评估集验证的可替换实现。
