# AI 面试就绪完善 Spec（v1）

状态：已实现（2026-08-15）

## 1. 目标

在不扩展业务领域、不引入复杂 Agent 框架的前提下，补齐面试演示中容易被追问的授权、反馈、实时体验和 RAG 口径问题：

1. 创建商品优化草稿必须来自显式的用户授权，不能只依赖自然语言关键词判断；
2. “没帮助”反馈必须能记录机器可分析的原因和可选说明；
3. 工作台和订单页 Agent 与统一对话使用一致的 SSE 优先、持久化查询降级策略；
4. 商品优化中的模型风险提示必须与有来源引用的规则 RAG 结论明确区分。

## 2. RAG 冻结区

本轮遵循现有 RAG v2 的评测驱动原则，以下内容保持冻结：

- 文档切分、BM25 风格词法评分和拒答阈值；
- Development/Test 固定评测集及指标门槛；
- 商家、平台、市场、类目和生效时间的召回前过滤；
- Agent 规则引用编号作用域和生成后确定性校验。

本轮只调整产品口径：没有经过 `search_platform_rules` 并返回有效引用的内容，只能称为“模型风险提示”，不得称为“规则校验结论”。所有改动后必须重新运行 `npm run rag:eval`，指标不得下降。

## 3. 显式草稿授权（P0）

### 设计

- Agent 请求新增 `allowDraftCreation`，默认 `false`；
- Web 仅在具备写权限的用户主动开启“允许本次创建草稿”时发送 `true`；
- 快捷“创建草稿”动作也必须显示并携带本次授权，不能由后端根据文本自动推断；
- `AgentRun` 持久化该授权，Worker 只从 MySQL 恢复，不信任队列 Job 或模型输出；
- 服务端仅在 `allowDraftCreation=true` 且角色为 admin/operator 时向模型暴露草稿工具；
- 每个 AgentRun 最多执行一次草稿工具，正式商品仍只能人工确认后写回。

### 验收

- 默认请求和 viewer 请求都不暴露草稿工具；
- 即使消息包含“优化/翻译”，未授权时也只能走只读工具或直接回答；
- 已授权 operator/admin 可以创建一条草稿；
- 队列重试继续由 `agentRunId` 唯一关联防止重复草稿。

## 4. 负反馈原因（P0）

- “有帮助”允许一键提交；
- “没帮助”打开原因弹窗，原因必选、说明可选且不超过 500 字；
- 复用现有 `AgentRunFeedback` 唯一键和 upsert API；
- 质量页继续按商家和时间窗口聚合原因分布。

## 5. Agent 实时状态复用（P1）

- 提供统一 `useAgentRunStream` Hook；
- 首选鉴权 SSE，展示持久化工具轨迹和终态；
- SSE 不可用时退回有界、可取消的 GET 查询；
- 组件卸载、切换商家或启动新运行时取消旧订阅，但不取消服务端任务；
- 终态包括 `COMPLETED`、`FAILED` 和 `CANCELLED`。

## 6. 模型风险提示与 RAG 结论（P1）

- 商品优化 Drawer 将 `complianceRisks` 标记为“模型风险提示”；
- 明确提示该字段没有规则引用，不能代替平台规则判断；
- 引导用户到规则知识库或 Agent 规则检索获得带引用结论；
- 不伪造引用，也不把未检索的模型知识包装为 RAG 结果。

## 7. 测试与交付

至少覆盖：

- DTO 默认值、授权持久化和 Worker 上下文恢复；
- 未授权/无角色/已授权三类草稿工具策略；
- 负反馈原因表单与 API 参数；
- SSE 成功、终态停止、失败降级和组件卸载；
- 中英文新增文案完整性；
- 完整 `npm run verify` 与 `npm run rag:eval`。
