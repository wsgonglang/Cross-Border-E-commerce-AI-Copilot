# 运营工作台与统一 AI 助手收敛 Spec v1

状态：已完成  
基线日期：2026-08-15

## 1. 背景

AI 对话与业务 Agent 已统一到服务端会话：每次用户消息都可以触发受控 Tool Calling，运行状态、工具轨迹、Token 用量和最终回答随会话持久化。

当前运营工作台仍嵌入旧的独立 `AgentPanel`。该面板自行创建无会话 Agent Run、轮询运行结果并展示工具轨迹，导致同一能力存在“工作台临时 Agent”和“AI 运营助手会话”两套交互模型。

工作台已有经营指标、异常待办、运行中任务和近期成果，但重要动作位于趋势图和商品表格之后；在窄屏中，AI 入口接近页面底部。基于计数规则生成的运营建议还使用 Agent 图标，容易让用户把确定性业务规则误认为模型判断。

## 2. 产品边界

- 运营工作台：发现异常、判断优先级、进入处理；
- AI 运营助手：对话、业务查询、工具调用、继续追问和草稿授权；
- AI 成果中心：统一审核、追踪和回溯 Agent 运行、商品草稿与任务成果；
- 批量任务/导入中心：查看异步执行进度和失败明细；
- AI 质量度量：查看成功率、失败率、反馈、时延和 Token 等治理指标。

工作台不再承载第二套完整 Agent 执行器，也不复制消息流和工具轨迹。

## 3. P0 范围

### P0-1：移除独立 Agent 执行器

- 从运营工作台移除 `AgentPanel`；
- 工作台不得直接调用 `runAgent` 或自行维护 `runId`；
- 保留现有 `AgentPanel` 组件供其他尚未迁移的业务入口使用，本阶段不做全仓删除。

### P0-2：建立统一 AI 助手入口

- 工作台提供轻量 AI 助手卡片，包括上下文说明、推荐问题和“打开 AI 运营助手”动作；
- 推荐问题跳转到 `/ai-chat` 并预填输入框，不自动发送；
- 预填信息使用 React Router navigation state，一次消费后清理，避免刷新重复注入；
- AI 助手继续使用全局商家/店铺上下文，时间范围直接写入推荐问题文本，不修改 Agent 协议。

### P0-3：调整首屏优先级

- 页面标题由“Agent 运营工作台”收敛为“运营工作台”；
- 经营指标之后立即展示“今日优先处理”和 AI 助手入口；
- 趋势、订单状态、热销商品和低库存明细下移为分析区；
- 基于确定性计数生成的建议使用“运营建议”语义，不再用机器人图标暗示模型生成。

### P0-4：保留安全边界

- viewer 入口文案明确只能使用只读工具；
- operator/admin 仍需在 AI 助手内单次授权，才可创建一条待确认商品草稿；
- 工作台快捷入口不得自动授权草稿创建，不得自动发送提示词；
- 正式商品写回仍必须经过既有人工确认流程。

## 4. P1 范围

### P1-1：统一执行与处理概览

- 将“运行中任务”和“近期 AI 成果”组织为统一的“执行与处理”区域；
- 左侧展示正在进行的 Agent 数和批量任务；
- 右侧展示等待处理或最近完成的成果；
- 不在工作台复制成果中心的筛选、详情和工具轨迹。

### P1-2：最近 AI 会话

- 工作台读取现有会话列表接口，展示最多 3 条最近活动会话；
- 展示会话标题、消息数、更新时间和运行状态；
- 点击会话进入 `/ai-chat` 并选中准确的 `sessionId`；
- 会话加载失败不阻塞经营工作台，卡片以局部错误或空状态降级。

### P1-3：精准深链接

- Agent 成果携带 `agentRunId` 时进入成果中心准确运行详情；
- 商品优化成果携带商品、优化记录信息时进入准确商品草稿；
- 缺少准确标识时降级进入成果中心列表；
- 批量任务继续进入批量任务中心，保持现有任务边界。

## 5. 明确非目标

- 不修改 Prompt、Provider、Agent Loop、工具 Schema、工具白名单和运行预算；
- 不修改 RAG 检索、阈值、引用校验、评测集或数据库迁移；
- 不新增多 Agent 编排、工作流画布、WebSocket 或新的消息系统；
- 不把工作台改造成第二个聊天页面；
- 不重构 AI 成果中心、质量度量和批量任务的服务端业务逻辑。

## 6. 验收标准

| 编号  | 验收项     | 完成标准                                             |
| ----- | ---------- | ---------------------------------------------------- |
| AC-1  | 单一入口   | 工作台不渲染 `AgentPanel`，不直接调用 `runAgent`     |
| AC-2  | 上下文预填 | 快捷问题进入 AI 助手后预填但不自动发送，且只消费一次 |
| AC-3  | 准确会话   | 最近会话点击后进入 AI 助手并选中对应会话             |
| AC-4  | 首屏顺序   | KPI 后先展示今日优先处理和 AI 助手，再展示趋势图     |
| AC-5  | 语义准确   | 确定性建议不再使用 Agent/AI 生成语义                 |
| AC-6  | 权限边界   | viewer 只读提示和草稿人工确认规则保持不变            |
| AC-7  | 降级行为   | 会话接口失败不影响经营指标、待办和图表展示           |
| AC-8  | 深链接     | 可获得业务标识的成果进入准确对象，缺失时安全降级     |
| AC-9  | 响应式     | 桌面与窄屏均无横向溢出，关键入口位于趋势图之前       |
| AC-10 | 工程验证   | 格式、lint、类型检查、Web 测试和生产构建通过         |

## 7. 测试要求

- AI 助手导航状态解析：合法预填、合法会话 ID、非法状态忽略、一次消费；
- 工作台 AI 入口：推荐问题和自由输入均只导航、不调用 Agent API；
- 最近会话：最多三条、准确链接、局部失败降级；
- 成果深链接：Agent Run、商品草稿和无标识降级；
- 保持现有认证恢复、商品优化和 AI 会话流式测试通过。

## 8. 验收结果

- 工作台已移除独立 `AgentPanel`，不再从工作台直接创建无会话 Agent Run；
- KPI 后首先展示“今日优先处理”和轻量 AI 运营助手入口，趋势与商品分析区后移；
- 快捷问题与自由输入均通过路由状态进入统一 AI 助手，只预填、不自动发送，状态消费后立即清理；
- 最近会话最多展示 3 条，后台生成会话显示运行状态，点击精确选择对应 `sessionId`；会话接口失败仅在卡片内降级；
- 运营建议改用确定性建议语义，并同时提供业务处理和“让 AI 分析”动作；
- 执行中任务与待处理成果收敛到“执行与处理”区域，商品草稿、Agent Run、批量任务和导入成果优先使用准确深链接；
- 新增 9 项导航、入口、降级与深链接测试；Web 共 55 项测试，全仓共 207 项测试；
- 真实浏览器验证快捷问题进入 AI 助手后保留在输入框且未发送，商品草稿进入准确优化记录；
- 390 px 窄屏下页面 `scrollWidth` 与视口同为 390 px，关键顺序为“今日优先处理 → AI 运营助手 → 趋势”，旧 Agent 执行入口不可见；
- `npm run verify` 通过：格式、lint、类型、i18n、207 项测试和生产构建全部成功；
- Docker Web 重建在构建容器中因内存上限以 137 退出，已使用同一源码的 Vite 页面完成浏览器验收；宿主机生产构建成功。
