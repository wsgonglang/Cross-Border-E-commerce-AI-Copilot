# AI 运行时一致性修复 Spec v1

状态：已实现

## 1. 背景与问题

AI 会话已经统一通过后台 Agent 运行，但取消链路还存在三个边界问题：

1. Agent 在最终回答写入会话后、运行状态更新前被取消时，可能出现 `CANCELLED` 运行带有最终助手消息；
2. 用户在创建运行接口返回 `runId` 前点击停止时，只能中止前端等待，后台运行仍可能继续；
3. AI 成果中心无法按 `CANCELLED` 筛选 Agent 运行。

这些问题属于现有能力的行为一致性缺陷，应在面试前修复。规则 RAG 的排序、阈值、引用校验和固定评测集不在本次范围内。

## 2. 目标

- 会话最终助手消息与 Agent `COMPLETED` 状态在同一数据库事务内提交；
- 取消先提交时，完成事务不得新增最终助手消息；
- 前端即使在 `runId` 返回前停止，也必须在拿到 `runId` 后补发服务端取消请求；
- 已知 `runId` 的停止操作在服务端确认后重新读取会话，避免首次刷新早于取消落库；
- 成果中心支持筛选 `CANCELLED` Agent 运行。

## 3. 验收标准

1. 条件更新 Agent 运行失败时，事务不创建助手消息，也不推进会话活动叶子；
2. 无会话 Agent 的条件完成更新返回失败时，执行链按取消处理；
3. 前端测试覆盖“停止早于 `runId` 返回”的竞态；
4. 服务端测试覆盖完成/取消原子边界和 `CANCELLED` 成果筛选；
5. `npm run verify` 与 `npm run rag:eval` 均通过；
6. 冻结的 RAG 核心文件无修改。

## 4. 非目标

- 不引入新的 Agent 框架、消息总线或分布式事务；
- 不修改模型规划、工具白名单或 RAG 检索算法；
- 不改变“AI 只创建草稿，人工确认后写回”的安全边界。
