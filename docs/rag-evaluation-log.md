# RAG 评测反馈记录

本文件记录规则 RAG 的失败样本、根因、改动和复测结果。它用于证明评测确实反向推动实现改进，不把固定小数据集的高分解释为生产准确率。

## 数据集约定

- `Development Set`：允许用于分析失败、调整分词、权重和阈值。
- `Test Set`：从 v3 开始冻结问题和期望结果；完成调参后才运行，不得为了让指标通过而修改标注。
- `Combined`：只用于查看总体回归，不作为调参依据。
- 当前 Test Set 的样本来自既有回归集，因此只称“从 v3 起冻结”，不宣称它们在历史上从未被开发者看过。
- 新发现的问题先进入 Development Set；只有经过人工确认、去重并发布新数据集版本后，才可调整 Test Set。

## 2026-08-15：实体词命中导致无依据回答

### 触发样本

```text
充电器保修期是几年
```

知识库只有充电器发布、电压和安全认证规则，没有保修期条款，因此期望行为是拒答。

### 修改前

- 返回文档：`electric`。
- 相关度：`0.878`。
- 查询覆盖率：`0.25`。
- 判定：`sufficient=true`，属于 false positive。
- 根因：两个商品实体相关词即可通过候选过滤，不能证明问题中的“保修期”属性得到正文支持。

当时 32 条容易样本的四项聚合指标均为 100%，说明只看总分没有暴露这个问题。

### 改动

- 最低命中词数由 2 调整为 3，短查询仍按实际词数处理。
- 将该问题及锂电池回收费用、食品进口关税、客户电话字段长度加入困难负例。
- 增加两个多文档问题；Recall@3 必须覆盖全部期望文档。
- 为“充电器保修期”增加独立回归断言，避免聚合指标达标却遗漏高价值 bad case。
- 将 38 条用例拆为 Development Set 24 条、Test Set 14 条，并从 v3 起冻结 Test Set。

### 修改后

- “充电器保修期”无候选结果，系统明确拒答。
- Development Set：Hit@1、Recall@3、MRR、拒答准确率均为 100%。
- Test Set：Hit@1、Recall@3、MRR、拒答准确率均为 100%。
- Combined 38 条：四项指标均为 100%。
- API 测试和完整工程验证通过。

### 结论

这次优化针对的是拒答边界，不代表所有实体相关的 unsupported query 都已解决。后续应继续收集真实运营问题，并优先观察拒答准确率与具体失败明细，而不是只追求聚合分数。
