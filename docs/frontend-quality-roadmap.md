# 前端与 AI 质量增强路线

基线日期：2026-07-30。

## 1. 背景与目标

阶段 0 至阶段 16 已经完成核心业务和 AI 闭环。当前项目不缺少页面或业务功能，后续工作转向校招“AI 全栈偏前端”岗位更容易验证的工程证据：

- 复杂前端交互可自动回归，而不只依赖人工浏览器验收；
- 页面按路由加载，复杂页面具备清晰的组件和状态边界；
- 服务端状态拥有统一缓存、失效、竞态和错误处理策略；
- 跨境后台至少具备中英文界面和一致的金额、日期本地化；
- AI 能力不仅记录运行轨迹，还能用接受率、成功率、时延和用量评估；
- 仓库首屏能让面试官在一分钟内理解产品价值和核心链路。

本路线不增加新的电商领域，不引入通用工作流画布、多 Agent 编排、模型市场、真实平台 OAuth、PWA 或复杂可观测基础设施。

## 2. 差距优先级

### P0：必须补齐

1. Web 缺少组件测试和端到端测试；
2. 所有业务页面被同步打入主包，生产构建存在大包提示；
3. 订单页和 AI 对话页接近千行，页面内部职责边界不够清晰。

### P1：完成 P0 后补齐

1. 服务端数据主要由页面手写 `useEffect`、`loading` 和刷新逻辑管理；
2. 跨境后台界面只有中文，界面语言与商品目标语言没有明确分离；
3. 缺少草稿接受率、工具成功率、时延和 Token 用量等 AI 质量指标；
4. README 缺少截图、短视频或 GIF 等低成本作品集入口。

## 3. 实施阶段

| 阶段                   | 优先级 | 范围                                                | 完成标准                                                                                                    |
| ---------------------- | ------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 17. Web 测试与性能基础 | P0     | Vitest、Testing Library、路由懒加载、统一路由加载态 | Web 至少覆盖认证路由和角色路由；所有业务页按路由拆包；构建不再把全部页面放入单一主包；CI 执行 Web 测试      |

| 19. AI 对话页模块化    | P0     | 会话导航、消息区、输入区、会话操作和分享拆分        | 流式取消、会话切换、收藏/归档/分享边界清晰；核心交互有组件测试；功能行为不变                                |

| 21. 后台国际化         | P1     | 中文/英文界面、金额/日期格式、界面语言设置          | 登录、导航、工作台、商品优化核心链路支持中英文；界面语言与 AI 目标语言独立；关键文案不散落在页面逻辑中      |
| 22. AI 质量度量        | P1     | 接受率、拒绝率、工具成功率、时延、Token 和失败率    | 指标来源可追溯、按商家隔离；工作台或成果中心提供轻量质量视图；明确说明小型 RAG 评估边界                     |
| 23. 作品集呈现         | P1     | README 首屏、截图、核心链路 GIF/视频、架构图        | 一分钟可理解项目；提供三步启动、演示账号和 3 分钟以内主链路演示；不暴露真实密钥或个人数据                   |

## 4. 实施顺序与停止线

严格按 17 → 23 推进，每阶段单独验证和提交。阶段 18、19 只重构职责，不顺带新增业务功能；阶段 20 只迁移高价值查询，不为所有接口建立抽象；阶段 21 先覆盖核心演示链路；阶段 22 只做可解释的基础指标；阶段 23 完成后停止扩大产品范围，转入简历描述和面试演练。

## 5. 统一验收要求

- 不修改 `ai-chat/` 和 `ecommerce-admin/`；
- 不改变服务端权限、人工确认、商家隔离和审计边界；
- 测试不得调用收费模型；
- 每阶段通过格式、lint、typecheck、相关测试和生产构建；
- UI 重构需要真实浏览器验证桌面与窄屏；
- 更新 `AGENTS.md`、README 或对应文档中的真实状态；
- 每阶段执行本地 `git add` 和 `git commit`。
