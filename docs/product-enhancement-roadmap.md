# 产品体验增强路线

基线日期：2026-07-29。

阶段 0 至阶段 15 已完成技术、核心业务闭环、成果中心、多店铺上下文、Agent 运营工作台、AI 会话生产力和结构化导入。本路线记录阶段 14 至阶段 16 的范围；阶段 14、15 已按下列验收完成，当前剩余阶段 16 的订单运营工作台。

- Agent 缺少全局入口，无法自然继承商家、店铺、商品和订单上下文；
- Agent 回答和工具轨迹刷新后丢失，草稿与批量结果缺少统一去向；
- 工作台只展示少量指标，缺少待办、异常、后台任务和可执行建议；
- 会话后端已有的重命名、置顶和分组能力未在前端呈现，也缺少归档、收藏、导出和受控分享；
- 批量任务原先只能选择已有商品，阶段 15 已补齐 CSV/XLSX 结构化导入；
- Merchant 被同时理解为租户和店铺，多店铺跨境业务无法表达；
- 订单页只有单一生命周期状态和简单详情，缺少运营视图。

## 1. 产品边界

本轮必须完成：

- AI 成果中心和可持久化 AgentRun；
- 全局商家/店铺上下文；
- 工作台经营分析、待办、Agent 建议和后台任务；
- 会话重命名、置顶、搜索、分组、归档、消息收藏、导出和内部分享；
- CSV/XLSX 商品与 SKU 导入；
- 店铺/销售渠道、商品刊登和店铺级订单；
- 订单多维状态、保存视图、批量操作和详情时间线。

本轮明确不做：

- Markdown、TXT、PDF 等非结构化文件的商品导入；
- 上传文件后未经预览和确认直接写入商品；
- 永久、匿名、公开的会话分享；
- Amazon、Shopee、Shopify 等真实平台 OAuth 或生产同步；
- 完整支付、物流、退换货和客服系统；
- 通用 ETL、BI 或多 Agent 编排平台。

规则知识库现有的 Markdown/纯文本导入保持不变；“不做 Markdown 导入”仅指商品、SKU 和批量优化入口。

## 2. 目标信息架构

```text
工作台
├── 经营指标与趋势
├── 待处理事项
├── Agent 快捷入口
├── 运行中后台任务
└── 最近 AI 成果

商品中心
├── 商品与 SKU
├── 店铺刊登
├── 库存
└── 商品导入

订单中心
├── 订单视图
└── 订单详情

AI 运营
├── 运营助手
├── AI 成果中心
├── 批量任务
└── 会话历史

知识与合规
└── 规则知识库

设置
├── 商家
├── 店铺/销售渠道
├── 用户与权限
└── AI 操作审计
```

应用顶部提供全局上下文切换器：

```text
当前商家 → 当前店铺/全部店铺 → 当前页面资源
```

页面可覆盖全局上下文，但必须在界面上明确展示覆盖结果。服务端仍以 URL 参数、用户归属和 RBAC 作为最终权限边界，不能信任前端上下文。

## 3. AI 运行与成果归属

### 3.1 最终事实

- Agent 的请求、回答、工具轨迹和运行状态由 `AgentRun` 保存；
- 商品生成内容继续由 `ProductOptimization` 保存；
- 批量进度继续由 `BatchOptimizationTask/Item` 保存；
- 正式商品与版本继续由 `Product/ProductVersion` 保存；
- 成果中心是统一查询入口，不复制上述业务内容。

建议的最小 `AgentRun`：

```text
AgentRun
├── id
├── merchantId
├── salesChannelId?
├── userId
├── sourcePage
├── input
├── answer
├── status
├── usage
├── startedAt
├── completedAt
└── toolCalls
```

`AgentToolCall` 可独立建表，保存工具名、服务端校验后的输入、裁剪后的输出、状态、错误和耗时。不得保存客户地址、刷新令牌或未经裁剪的敏感数据。

### 3.2 成果中心

成果中心至少支持：

- 按商家、店铺、来源、成果类型、状态和创建时间筛选；
- 查看待确认、已应用、已拒绝和失败的商品草稿；
- 查看 Agent 运行回答和工具轨迹；
- 查看批量任务及每一项的关联草稿；
- 跳转到准确商品、订单、任务和会话；
- 从待确认草稿直接进入对比审核；
- 状态变化后同步刷新工作台、商品页和任务详情。

禁止只展示无法操作的内部 ID。每个 ID 必须配套业务名称和可访问深链接。

## 4. 阶段计划与完成标准

### 阶段 11：AI 成果中心

状态：**已完成（2026-07-29）**。已通过自动化测试、真实 MySQL/Compose API 联调和浏览器交互验收。

范围：

- `AgentRun/AgentToolCall` 模型、迁移、Service 和 API；
- Agent 执行成功、失败和工具轨迹持久化；
- 成果中心聚合接口和页面；
- Agent、商品草稿、批量任务之间的业务深链接；
- 工作台先显示最小的待确认数量和最近成果入口。

关键验收：

1. Agent 创建商品草稿后刷新页面，运行记录仍存在；
2. 成果中心能找到该运行和草稿；
3. 点击草稿能打开准确商品和优化记录；
4. 应用或拒绝后成果状态同步；
5. 跨商家访问返回 403/404；
6. 失败 AgentRun 保存错误但不泄露模型密钥或敏感业务数据。

### 阶段 12：店铺与全局上下文

状态：**已完成（2026-07-29）**。已通过自动化测试、真实 MySQL/Compose API 联调和浏览器上下文切换验收。

范围：

- `SalesChannel` 或 `Store`；
- `ProductListing` 保存店铺级标题、语言、价格、外部编号和发布状态；
- Order 关联销售渠道；
- 全局商家/店铺切换器；
- 管理店铺页面；
- 至少两个店铺的演示数据。

关键验收：

1. admin/operator 可在授权商家内管理店铺；
2. 切换店铺后工作台、商品刊登、订单和 Agent 上下文一致；
3. 一个主商品可拥有多个店铺刊登；
4. 不允许跨商家关联店铺、商品或订单。

### 阶段 13：Agent 运营工作台

状态：**已完成（2026-07-29）**。已通过自动化测试、真实 MySQL/Compose API 联调和浏览器店铺/时间范围/Agent/窄屏验收。

范围：

- 日期范围和上一周期比较；
- 销售、订单、客单价、退款和库存预警；
- 订单状态分布、销售趋势、热销商品和低库存列表；
- 待确认草稿、失败任务和待处理订单；
- 上下文 Agent 快捷输入；
- 运行中 Agent/批量任务和近期成果。

不得展示没有真实数据来源的访客、转化率或预测指标。

关键验收：

1. 工作台所有数字可由真实订单、商品、任务或成果数据复算；
2. Agent 能继承当前商家、店铺和时间范围；
3. Agent 建议必须附业务依据和后续操作入口；
4. viewer 只可查询，operator/admin 才可创建草稿或任务。

### 阶段 14：AI 会话生产力

状态：**已完成（2026-07-29）**。已通过自动化测试、真实 MySQL/Compose API 联调和浏览器交互验收；验收中额外修复了人工重命名被首条消息自动标题覆盖、永久删除成功后前端仍显示确认框的问题。

范围：

- 重命名、置顶、搜索和分组；
- 会话归档与恢复，删除作为二次确认的最终动作；
- 收藏单条消息；
- 导出 Markdown/JSON；
- 内部只读分享快照、有效期、撤销和访问审计；
- 从消息创建成果或关联业务对象。

关键验收：

1. 所有操作服务端鉴权并持久化；
2. 归档会话默认不出现在活动列表；
3. 分享只允许已登录且被授权用户访问；
4. 分享撤销或过期后立即不可访问；
5. 导出和分享对订单客户信息做脱敏。

### 阶段 15：结构化导入中心

范围：

- CSV/XLSX 上传；
- 工作表、表头和字段映射；
- 商品/SKU 行级校验和预览；
- 有效行、无效行、警告和覆盖风险；
- `ImportJob/ImportItem` 持久化；
- BullMQ 异步处理、重试、幂等和取消未执行项；
- 失败明细 CSV 下载；
- 可选择“仅导入商品草稿”或“导入后创建 AI 优化任务”。

推荐解析边界：

- CSV 使用流式解析；
- XLSX 只读取值和基础单元格，不执行公式、宏或外部链接；
- 文件类型、大小、工作表数和行数必须限制；
- 文件哈希和幂等键避免重复提交。

关键验收：

1. 映射和预览前不写业务数据；
2. 无效行不会阻塞有效行，但失败原因可下载；
3. 同一幂等键不会重复创建商品或任务；
4. 跨商家商品编码和 SKU 校验生效；
5. 导入结果进入成果中心并可跳转。

### 阶段 16：订单运营工作台

范围：

- 保留订单生命周期状态，增加最小 `paymentStatus`、`fulfillmentStatus` 和 `salesChannelId`；
- 默认视图和用户保存视图；
- 关键词、时间、金额、店铺、支付、履约和退款组合筛选；
- 排序、列显示、分页和批量操作；
- 独立详情页或宽 Drawer；
- 订单时间线、商品、客户、地址、金额、物流和操作日志；
- 订单上下文 Agent。

关键验收：

1. 保存视图可恢复筛选、排序和列配置；
2. 批量操作逐单执行权限、状态机和幂等校验；
3. 部分失败返回逐单结果，不能把整批错误伪装成成功；
4. Agent 只能读取裁剪后的订单数据，不获得客户邮箱和完整地址；
5. 工作台订单待办与订单页视图一致。

## 5. 行业对照

本路线只借鉴信息架构和交互，不复制生产平台的全部复杂度：

- Shopify Home：指标、订单待办、建议卡片、Sidekick 建议和后台任务；
- Shopify Orders：保存视图、组合筛选、列配置和批量操作；
- Shopify CSV：上传、预览、确认、导入和失败处理；
- Medusa Admin：Store、Region、Sales Channel、Location、Currency 和 Locale 分离；
- Saleor：Channel 作为多地区、多货币和多 storefront 的核心边界。

## 6. 统一工程约束

阶段 11 至阶段 16 继续遵守：

- `ai-chat/` 与 `ecommerce-admin/` 只读；
- 服务端 RBAC 和商家隔离是最终安全边界；
- Agent Tool 只调用业务 Service；
- AI 和文件导入默认只创建可审核草稿；
- MySQL 保存最终业务状态，Redis 只负责队列和短期进度；
- 写操作必须校验、幂等、审计并提供失败路径测试；
- 每阶段通过 `npm run verify`、真实依赖联调、文档更新和本地 Git 提交后才能标记完成。
